    16. Changelog

    2026-11-05 — Free Vercel breed advisory API and Android client

    • Added advisory-api/, a dependency-free Vercel Node.js function (GET /api/advisory) serving all 68 breeds with origin, utility, milk yield, physical markers, market price and schemes.
    • Added dynamic female-adult, male-adult, calf, young and fallback advisory cards; calf responses include a vaccination/deworming timeline. Milk yield is hidden for males and calves; draught advice is hidden for females and calves.
    • Added en/ta/hi copy, localized breed names and scheme names, CORS *, 5-second client timeout and offline fallback.
    • Added breed-classifier-react/src/services/onlineAdvisory.js with fetchAdvisoryData(...); it never throws and degrades to an on-device-only message when offline or slow.
    • Breed Tips now opens whenever the device is online; the legacy Online Mode / backend-health gate was removed for this free API, and offline copy was updated.
    • Deployed the API to Vercel production at https://advisory-api-bharaths31s-projects.vercel.app/api/advisory and wired that URL as the default advisory endpoint in the Android client. The Breed Tips modal now renders the live advisory cards, vaccination timeline and schemes.
    • Added a browser landing page at / so the deployment base URL is no longer a 404, and disabled Vercel Authentication protection for public API access.
    • Verified with 7 API tests, a live local HTTP request, and a browser import of the Android client.

    2026-11-05 — Center-focused guardrail, top-k OOD and selfie blocker

    • Center-focused Stage A: straight-edge and flat-patch checks now run on the central 180×180 region, with only a high-threshold global fallback. Barn roofs, fences, sky and other border clutter no longer reject a valid animal.
    • Human selfie gate: checkHumanSelfie() uses the browser FaceDetector when available, then a pure-JS YCbCr fallback (central skin ratio, 5×5 skin smoothness, bilateral skin symmetry, dark hair cap and eye/brow density). Close-up selfies return human_or_selfie before any breed prediction.
    • Top-k OOD: single-class Z_peak/Z_max rejection was replaced by top-3/top-5 breed-mass checks plus a relaxed entropy ceiling. Breeds that split probability across visually similar classes (Sahiwal/Gir, Hallikar/Khillari) are no longer falsely rejected. Binary confidence, energy and MSP floors remain.
    • Verification: all 34 cattle test images accepted; human selfie and monitor screenshot rejected. Live two-canvas verifyDynamicPredictions() passes, and client build/tests/i18n are green.

    2026-11-05 — Direct 260×260 input, native camera, developer-mode simple UI

    • Camera/silhouette removal: Android now uses native <input type="file" accept="image/*" capture="environment"> for Take Photo and the gallery file input for Upload. The custom getUserMedia camera modal, silhouette HUD, foreground/contour guidance and Android camera optimization path were removed from the Android flow. The shared web CameraCapture silhouette overlay was also removed.
    • Direct downscale: both input paths decode once and draw directly to the 260×260 model canvas. Gallery pad/center/manual crop remains; the Auto/Train-Match downscale setting was removed.
    • Active ONNX model field removed: the home model/WASM/size/latency panel is gone.
    • Developer mode: Advanced Settings has a Developer mode switch (default off). Off = simplified home/result/settings: no ONNX/WASM, model telemetry, inference strip, rank/model-match badges, top-N Softmax spectrum, confidence percentages, scientific names or method text. On = full diagnostics, OOD/model controls and display settings. Recent scans are hidden when empty in simple mode and old scans without guardrail data are filtered from the ledger.
    • Zero-static estimator retained: the dynamic guardrail and dynamicAgeGender.js compute all values from the current 260×260 pixels and 68 logits; no breed-lookup age/gender fallback.
    • Verification: build, tests and i18n pass; simple/developer modes verified in the browser harness and on the connected Android device.

    2026-11-05 — Multi-stage object/monitor guardrail and biometric age/gender

    • Stage A image gate (src/utils/imageGuardrails.js): Sobel-based axis-aligned edge/bezel detection, contiguous straight-edge spans, blue-cast / dark-bezel screen check, a 16×16 flat-block wall/background check with an adaptive strong-edge exception, and a whole-frame skin-dominance check for close-up people/selfies. Runs on the prepared 260×260 canvas before a prediction is accepted.
    • Stage B logit gate: normalized 68-class entropy, top-logit Z-score peak, binary-confidence floor, energy and MSP checks. Rejections return rejected: true with no species/breed and a localized reason.
    • Model-calibrated thresholds: the shipped lite2_v27 model’s raw thresholds from the original brief rejected every valid test cattle image. The final thresholds were calibrated against the test set (EDGE_SPAN_MAX 0.62, entropy 0.76, Z_peak 2.0, Z_max 1.6, binary floor 0.60, energy floor -3.2004). Valid cattle pass; the screen screenshot, human selfie and goat test image are rejected.
    • Biometric estimator (src/services/biometricAgeGender.js): juvenile/heavy breed logit mass, foreground bbox/torso fill/crown-texture biometrics, fused age scores, and gender from draught vs dairy breed mass + neck/hull ratio.
    • Corrected MSP: on-device MSP now uses the binary species head, matching the Python OODDetector.compute_msp, instead of the breed-head probability.
    • Result UI: a rejection card replaces the dossier for rejected images with a localized reason and retry action; rejected scans are not added to recent scans. Gender/age remain read-only.
    • Verification: 35 cattle images accepted (including the 0.4688 flat-patch cases through the adaptive strong-edge exception); the app screenshot (monitor UI), a human selfie and the goat image are rejected. Client build/tests and i18n checks pass.

    2026-11-04 — Self-describing .pt / .onnx models (zero external JSON)

    • src/model_introspect.py: unified loading/introspection for PyTorch and ONNX. Architecture is auto-detected from tensor shapes (backbone from the first MBConv width, CBAM vs SE from the spatial conv, head widths/counts from the final layers) and from the ONNX graph (input resolution, output widths, float16 I/O). Returns a LoadedModelBundle with the correct transform, inverse class maps, embedded OOD thresholds and a Dev-Console spec summary.
    • Normalization fix: bundle.transform stops at ToTensor() when the graph already bakes ImageNet mean/std (_MobileOutputs, *_mobile* ONNX), eliminating double normalization. Caller-normalized .pt / _RawOutputs ONNX still get Normalize.
    • scripts/embed_metadata.py: --all, --file, --inspect CLI that writes class maps, preprocessing, resolution, normalization mode and OOD thresholds into existing files. .pt metadata lives in ckpt["model_meta"] (TorchScript uses an extra model_meta.json); ONNX uses metadata_props. Writes are atomic and weights are untouched.
    • Exports/training: src/export.py embeds metadata after ONNX, ONNX-INT8 and FP16 exports and into portable model.pt; src/train.py embeds it in every checkpoint and re-embeds calibrated OOD thresholds after training.
    • Runtime: test_model.py and server/ now load through LoadedModelBundle, use per-model class maps (50- and 42-class models can coexist), cast float16 ONNX inputs automatically, and prefer embedded OOD thresholds (legacy JSON is still honoured for old artifacts). Uploads are embedded + validated on arrival.
    • Robustness: legacy 7-layer binary heads (v17/v22/v9 portable bundles) are rebuilt from tensor keys; class maps are only accepted when their length matches the head width.
    • Docs: new Self-Describing Models page.

    2026-09-23 — Tail-bias regression fix: single imbalance mechanism, safe mixing, EMA, soft routing, timestamped outputs

    Diagnosed from a 10-photo ONNX batch test (0/10 correct; top-5 dominated by rare breeds; a Gir bull predicted as a rare breed) that regressed after the 2026-09-21 overhaul.

    Imbalance (src/config.py, src/data_pipeline.py, src/train.py): - LOGIT_ADJUST is now False by default — the effective-number sampler is the single long-tail mechanism. Enabling both double-corrects and over-predicts rare breeds at inference. --logit-adjust re-enables it; its prior is computed from the effective sampled distribution (--logit-adjust-prior sampled|raw), never raw counts. Startup prints the active mechanism and prior max/min ratio. - Fixed _effective_num_weights divide-by-zero for classes absent from train (previously produced NaN logit-adjustment priors).

    Mixing (src/config.py, src/data_pipeline.py, src/train.py): - CutMix/MixUp now pair within the same species (_pairing_perm), so binary labels stay one-hot and breed targets stay proper distributions. - Strength reduced: CUTMIX_MIXUP_PROB 0.5→0.25, CUTMIX_ALPHA 1.0→0.4, MIXUP_ALPHA 0.3→0.2. Rare-class guard kept. - MIX_OFF_LAST_FRAC=0.15 disables mixing for the last 15% of phase 2.

    Augmentation OFF by default (src/config.py, src/data_pipeline.py): - flip / ColorJitter / RandAugment / RandomResizedCrop / mixing are opt-in via --mix --flip --color-jitter --randaugment --rrc --augment-all. With all off, the train transform equals the eval transform.

    EMA (src/train.py): - Updated once per optimizer step (was twice per micro-batch with grad_accum=2), with warm-up decay_t = min(0.999,(1+t)/(10+t)). - Startup prints steps/epoch, total optimizer steps and the EMA time constant, warning if it exceeds 25% of phase-2 steps. Every eval logs BOTH raw and EMA metrics and saves whichever scores better.

    Motivated by a graph-assisted gap analysis: phase-2 best val top-1 was 0.578 (binary 0.95, cattle 0.59, buffalo 0.61), with 21+ indigenous cattle breeds carrying ≤14 images against gir=768, and the old 85/10/5 split leaving many rare breeds with zero test images.

    Imbalance (src/data_pipeline.py, src/train.py): - Logit adjustment (Menon et al., ICLR 2021): tau·log(prior) added to breed logits during training only, from smoothed train priors (compute_class_priors). - Long-tail split minimums: every (species, breed) with ≥3 images now gets ≥1 val and ≥1 test image; fixed grouping to key on (species, breed) because bargur exists under both species. - Rare-class mixing guard: breeds below RARE_CLASS_THRESHOLD (30 train images) are excluded from CutMix/MixUp (compute_rare_classes + keep mask). - Adaptive loss weights: once binary_acc ≥ 0.95, weights switch from 0.15/0.50/0.35 to 0.05/0.55/0.40 to reallocate budget to the breed heads. - --no-mix now actually disables mixing (previously it only swapped the collate fn).

    Soft routing: BreedClassifier.predict(), test_model.py, and both Flutter engines (android_tflite_engine.dart, web_tfjs_engine.dart) now mix p(species)·softmax(head) across all 75 breeds instead of hard binary argmax, removing two-stage routing error propagation.

    2026-09-20 — Accuracy/Efficiency Overhaul: Distillation, EMA Fix, Mobile INT8 Exports
