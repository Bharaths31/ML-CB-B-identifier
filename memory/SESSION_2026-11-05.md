# Session 2026-11-05

## Scope

This session covered four connected workstreams:

1. On-device guardrails and dynamic age/gender.
2. Android input simplification and Developer Mode.
3. A center-focused guardrail/selfie/top-k rewrite.
4. A free Vercel advisory API, deployment and Android integration.

## Timeline

### Phase A — Initial guardrail and biometrics

- Built a Stage A geometry gate (Sobel edges, straight-edge ratio, flat blocks)
  and Stage B logit checks (entropy, Z-peak, binary confidence, energy, MSP).
- Calibrated thresholds against the shipped `lite2_v27` model because the
  original brief values rejected every valid cattle image.
- Added a dynamic age/gender estimator, then replaced the earlier
  foreground-mask biometric estimator.
- Added rejection UI and excluded rejected scans from Recent.

**Observation:** The first global geometry thresholds were too aggressive for
farm backgrounds and the single-class peak checks were too strict for similar
breeds.

### Phase B — Simple UI, direct input, native camera

- Removed the custom Android camera modal and silhouette HUD.
- Android Take Photo uses a native camera file input; gallery uses a normal file
  input.
- Both paths draw directly to `260×260`.
- Removed the Home Active ONNX model telemetry card.
- Added Developer Mode (default off) and hid model/OOD/diagnostic UI in simple
  mode.
- Removed the silhouette HUD from shared `CameraCapture`.
- Verified simple mode on the connected iQOO device.

### Phase C — Center-focused guardrail and top-k OOD

**Problem:** Valid cattle were still rejected because barn roofs/fences/sky
activated global straight-edge/flat checks, and similar breeds split probability
across Top-2/Top-3.

**Changes:**
- Stage A now analyzes a central 180×180 box.
- Added a human selfie gate:
  - `FaceDetector` when available;
  - YCbCr fallback with central skin ratio, 5×5 luma sigma, bilateral symmetry,
    dark hair cap and eye/brow density.
- Stage B now uses top-3/top-5 breed mass and a relaxed entropy ceiling; removed
  single-class Z-peak rejection.
- Added `human_or_selfie` rejection reason and localized copy.

**Calibration results:**

| Image | Result |
|---|---|
| 34 cattle images | Accepted |
| `img13` / `img22` / `img34` flat-patch `0.4688` | Accepted via top-k |
| Human selfie | Rejected `human_or_selfie` |
| Monitor screenshot | Rejected `manmade_object_or_screen` |
| Goat | Accepted (known trade-off) |

**Observation:** `FaceDetector` was unavailable in the Electron harness and the
Android WebView, so the YCbCr fallback was the effective path.

### Phase E — Deployment troubleshooting

**Symptom 1:** `https://advisory-api-rho.vercel.app/` returned 404.

**Cause:** There was no `/` route; only `/api/advisory` existed.

**Fix:** Added `advisory-api/public/index.html` with a live advisory form.

**Symptom 2:** After authenticated deploys, `/api/advisory` also returned 404.

**Cause:** Vercel was building the repository root, not `advisory-api`. Build
logs showed a clone of the repo root and an empty output. The project Root
Directory was unset.

**Fix:** `vercel project update advisory-api --root-directory advisory-api`.

**Symptom 3:** The canonical deployment redirected to Vercel Authentication.

**Cause:** `ssoProtection` was set to `all_except_custom_domains`.

**Fix:** `vercel project protection disable advisory-api --sso`.

**Result:** Both `/` and `/api/advisory` return 200 on the canonical URL.

**Symptom 4:** The first authenticated deploy from inside `advisory-api` failed
with "Root Directory advisory-api does not exist" because the local upload root
was already `advisory-api`.

**Resolution:** Use the Git integration with the project Root Directory set to
`advisory-api`. Avoid deploying from inside the subfolder when the project root
is also that subfolder.
